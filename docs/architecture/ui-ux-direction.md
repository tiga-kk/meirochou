# UI/UX 改善および設計のフィードバックバックログ

移行計画のプレビュー段階（Task 3完了時点）において、人間がプレビューテストを行う中で浮き彫りになったUI/UXの課題と、今後の改善に向けたメモです。

## 課題一覧

### 1. UIが「AI臭い」問題
- **現状の懸念**: 丸みのあるフォントやピル型のチップ、過剰なグラデーション、画一的なカードなど、「いかにもAIが自動生成したUI」という印象が残っています。
- **改善方針**:
  - `AGENTS.md` に記載の「紙面/カタログ感を出し、非AI感を高める」という方向性をより徹底する。
  - フォントを丸ゴシックから明朝系（`"Hiragino Mincho ProN"`, `"Yu Mincho"`, `"Noto Serif JP"` 等）へ寄せる。
  - 余計なグラデーションやカードの影、極端な角丸（ピル型）を減らし、細い実線や適切な余白によるグリッド設計で、実用性の高いツールらしい美しさを目指す。

### 2. メタな設計（UX）がユーザーにフレンドリーか不明な点
- **現状の懸念**: コミケ会場でスマホを片手操作する現場での実用性を重視した際、画面遷移や情報レイアウト、操作ステップ（ピンのタップからボトムシートの立ち上がり、お品書きモーダルの開閉など）が本当に直感的で扱いやすいか確証がありません。
- **改善方針**:
  - 実機（スマートフォン）幅での片手親指での押しやすさ、各ボタンのタップ領域（44px以上）、視線誘導を検証する。
  - 現地での「購入」「保留」操作の手数、地図での現在地切替（東・西エリア）の動線をシンプル化する。

### 3. お品書き一覧の画像並びの最適化問題
- **現状の懸念**: お品書きを一覧表示（全画面モーダル内）した際、各画像のサイズやアスペクト比の最適な組み合わせで綺麗に整列して並ばず、視認性が低下している可能性があります。
- **改善方針**:
  - Masonry（レンガ状）レイアウトや、画像サイズ・アスペクト比に応じた適切なグリッド/フレックス比率の動的調整を導入する。
  - お品書き画像とサークル情報テキストのバランスを最適化し、一覧スクロール時のカクつきを抑える。

## 人間がプレビューする際の重点チェックポイント

この段階（ベースライン移行中）で動作プレビュー（`npm run dev:webapp` 等での動作）を人が評価する際、特に注力すべき観点は以下の通りです。

1. **実機（スマホ）幅でのレイアウト崩れの有無**
   - 画面幅が極端に狭いスマホ（iPhone SEなど）でも、ヘッダーの情報やボトムシート、お品書きモーダルが重ならず正しく描画されるか。
2. **ピンの地図追従性とジェスチャー挙動**
   - 地図をピンチズーム・パンした際に、サークルピンの位置がズレずに地図座標にぴったり固定されたまま追従するか。
   - ズーム倍率を変更してもピンが不自然に巨大化したり極端に小さくなりすぎたりしないか。
3. **ボトムシートと地図ピンの連動性**
   - ピンをタップした際、下から立ち上がるボトムシートに正しいサークル情報（スペース番号、優先度、お品書き）が表示されるか。
   - お品書き一覧モーダルでサークルカードを選んで閉じた後、地図上で該当するピンとボトムシートが選択状態に戻るか。
4. **「購入」「保留」のステータス更新と視認性**
   - 「購入」を押した際のピン消去（または暗転）、「保留」を押した際のピンの色変化などが視覚的に分かりやすく、片手でスムーズに切り替えられるか。

## Phase 4 management UI contract

- 管理機能は既存の設定入口から開き、地図・経路画面を恒常的な管理ダッシュボードへ置き換えない。
- event/day selector、source manager、outbox panel、削除操作は独立したlight-DOM Lit componentとし、repository、service、fetch、LocalStorageを直接参照しない。
- source diffと削除確認はスマホ全画面dialogにし、focus trap、Escape cancel（非破壊操作のみ）、背景inert、閉じた後のfocus returnを実装・テストする。
- event/day selectorはatomic transitionの成功後にだけ選択表示を確定する。読込失敗時は旧map/state/選択値を維持する。
- GAS URL全体を表示できるのはユーザーが編集するURL inputだけとする。summary、error、outbox row、logにはservice/view-modelが作るhost-only表示を使う。
- pending outbox、busy、未設定、削除警告は色だけで伝えず、本文・accessible name・live regionを併用する。
- Pixel 5幅で全操作対象44×44 CSS px以上、横overflowなし、safe-area inset対応、200% text zoomで主要操作が欠けないことを確認する。
