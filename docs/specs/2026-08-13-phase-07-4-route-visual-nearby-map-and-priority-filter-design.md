# Phase 7.4 経路表示信頼性・周辺地図・優先度フィルター設計

## 目的

Phase 7.3までに残った経路表示の実機視認性、一覧以外の購入Undo、実GAS確認の未完事項を閉じる。同時に、次の新しい利用者向け機能を追加する。

- 経路案内を開始しなくても会場地図を単独で閲覧できる。
- 地図上の任意地点、または現在地を基準に、近い未購入サークルのお品書きを地図上へ表示できる。
- 周辺表示件数を5 / 10 / 15 / 20件から選べる。
- 優先度を完全一致の複数選択で絞り込める。
- 同じ優先度条件を通常の経路案内の巡回対象にも適用できる。

このPhaseでは新しい地図ライブラリ、ルーティングエンジン、状態管理基盤を導入しない。既存のmap bundle、grid routing、`GestureZoomController`、Circle Status、Route Guidanceを再利用する。

## 外部挙動

### 1. 現在経路と候補経路

現在経路は次を満たす。

- 赤系のbase pathが常時見える。
- motion有効時だけ、進行方向を示すmoving cueを表示する。
- moving cueは実時間で動くだけでなく、390px幅の実画面で方向が視認できる。
- reduced motionではmoving cueを停止するが、base pathと静的な方向cueは残す。
- ルートの見た目を直すために毎frameのroute再計算、SVG再生成、JavaScript timer更新を追加しない。

候補経路は青系の静的表示とする。候補経路へcurrent routeと同じloop animationを付けない。既存の候補選択・比較・確定状態は変更しない。

### 2. 優先度フィルター

優先度は既存Galleryと同じ意味を使う。

- `10`と`9`を選択した場合は、priorityが10または9のサークルだけが対象になる。
- 閾値条件（「9以上」等）は導入しない。
- 複数選択できる。
- 何も選択していない状態は「すべて」。
- priorityが未設定または数値として解釈できないサークルは、特定priority選択時には一致しない。
- Gallery、周辺地図、経路案内で判定規則を一致させる。

### 3. 経路案内へのフィルター適用

経路案内では、現在の未購入かつ非保留サークルから優先度条件に一致するものだけを`pendingCircles`としてRoute Guidanceへ渡す。

- フィルターはALNSの評価関数を変更しない。
- フィルター済み候補だけで初期目的地、距離行列、ALNS対象、`bestOrder`を構成する。
- 保留サークルは従来どおり巡回対象外。
- 進行中の案内中にUI上のpriority選択を変更しても、現在経路を勝手に変更しない。
- 新しい条件を適用するのは、ユーザーが明示的に再計算または通常の検索開始操作を行ったときだけ。
- route snapshotは実際の`bestOrder`を保存するため、フィルター済み経路の再開を維持する。Phase 7.4ではpriority選択UI自体を永続化するためだけの新しいstorage schemaを追加しない。

### 4. 独立した地図閲覧モード

ヘッダーに「地図」を追加し、経路案内の開始状態に依存しない全画面の地図閲覧モードを開けるようにする。

- `navigation-map`のDOMをそのまま流用して移動させない。
- map area / map assets / grid routing / zoom計算などの既存ロジックは再利用する。
- Route Guidance Sessionとは別の一時的な表示状態として扱い、地図閲覧だけで現在経路、現在地、目的地、snapshotを変更しない。
- 複数areaがある場合はareaを選択できる。
- 初期areaは、現在地フォームが有効なareaならそれを使い、それ以外は未購入サークルが存在する最初のareaとする。

### 5. 周辺サークル表示

検索基準地点は次の二通り。

1. 「現在地を使う」: 現在地フォームから解決できる位置を使う。
2. 「基準地点を変更」: 明示的な選択モードに入り、次の地図1タップを検索基準地点として使う。

通常のパン操作を地点指定として誤認しない。地点指定モード外の地図タップは検索基準を変更しない。

地図タップは表示座標から元画像座標へ変換し、対応するgrid cellを求める。blocked cellを選んだ場合は近傍の最寄りwalkable cellへ補正する。妥当な補正ができない場合は選択を拒否して既存基準地点を維持する。

周辺候補の処理順は次のとおり。

1. 選択areaの未購入サークルを取得する。
2. 通常は保留サークルを除外する。「保留も表示」を有効にしたときだけ含める。
3. priority条件で絞る。
4. 検索基準grid indexから一度だけ距離mapを構築する。
5. 到達可能サークルをwalkable grid距離の昇順に並べる。
6. 指定件数5 / 10 / 15 / 20件で切る。

ユークリッド距離やspace番号順を「近い」の代用にしない。

### 6. お品書きの地図オーバーレイ

周辺サークルは、サークル位置のanchorとお品書きカードをleader lineで結んで表示する。

- 画像は既存Circleの`tweet`を使用する。
- 画像がない、または読込失敗時は既存Galleryと同等のplaceholderを使う。
- カードには少なくとも`space`とpriorityを表示する。
- カードタップは既存のお品書き拡大表示へ接続する。
- 初期実装ではカードから購入、現在地変更、経路変更を直接行わない。
- カードは地図stageと一緒にpan / zoomする。カードだけを逆scaleして固定サイズにする複雑な仕組みは導入しない。
- 配置は決定的な単純貪欲配置とし、各anchorの周囲に定義した候補位置を順番に評価して、既配置カードとの重なりが最小の位置を選ぶ。
- 力学シミュレーション、外部レイアウトライブラリ、常駐animation loopを導入しない。

### 7. 一覧以外の購入Undo

Galleryで成立している「最新1件だけUndo」の契約を、通常の現在目的地画面からの購入にも適用する。

Undoは最低限次を戻す。

- Circle Status
- 逆向きGAS outbox
- 購入前のRoute Guidance Session snapshot
- 現在画面のroute / pin / count表示

保留操作はUndo対象へ広げない。複数段Undo履歴も作らない。

### 8. 残る実機・外部確認

次はコード変更と混同せず、Phase終端の受入確認として扱う。

- current route moving cueの実機視認性。
- candidate routeが静的でcurrent routeと混同しないこと。
- C108で任意地点からの周辺検索が実際のwalkable grid距離順になること。
- 390px / 200% zoomで新しい地図UIが横overflowしないこと。
- 実GASで同一space再送が既存行更新になり、既存Sheet列を壊さないこと。
- Phase 7.3 Task 4の地図drag遅延は、実機で再現できる場合だけ証拠を取り直す。再現根拠なしに別のgesture実装へ置換しない。

## 対象外

- GPS、加速度センサ等による自動現在地推定。
- 複数areaをまたぐ一枚地図化。
- 周辺カードの自動クラスタリング。
- お品書き画像のOCR。
- priority閾値検索。
- priorityフィルターのLocalStorage設定保存。
- 周辺地図上からの購入・保留・目的地確定。
- 新しい地図library、physics engine、UI framework。
- ALNS目的関数、時間減衰、queue service timeの変更。
- 地図drag遅延について証拠のない全面書き換え。

## テスト原則

- route animationは`animation-name`やCSS定数の存在だけで合格にしない。
- 390px相当viewportでcomputed animation valueの時間変化と、screen-spaceで読める表示契約を分けて検証する。
- priority filterは未選択、単一、複数、未設定priorityをテーブルテストする。
- 周辺順位は障害物を含む小さなfixtureで「直線距離は近いがgrid距離は遠い」ケースを入れる。
- blocked origin補正を純粋関数で検証する。
- お品書き配置は同一入力から同一配置になること、カードがanchor情報を失わないこと、5 / 10 / 15 / 20上限を検証する。
- 経路案内フィルターはStartだけでなくALNS入力へ対象外spaceが混入しないことを確認する。
- Undoはstatusだけでなくroute snapshotとGAS outboxまで検証する。
- visual snapshotはheaded確認後に意図した差分だけ更新する。
